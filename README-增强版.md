# TGbot-D1 3.0.5 增强版说明

本文件是 Fork（realadmin/TGbot-D1）对原作者 [moistrr/TGbot-D1](https://github.com/moistrr/TGbot-D1) 的增强说明。
原项目未附开源许可证，本 Fork 通过 GitHub 站内 Fork 机制分享，代码著作权归原作者所有；增强部分仅供个人学习与自用部署。

增强版文件：`TGbot-D1创新版本3.0.5-增强版.js`（基于原版 `TGbot-D1创新版本3.0.5.js` 修改，原版文件未改动）。

**部署请看专门为本增强版重写的教程：[部署教程-增强版.md](部署教程-增强版.md)（小白向）。** 本仓库自带的原版教程（3.0.0 教程与 PDF）是给原版用的，其 setWebhook 示例缺少 `secret_token` 与完整的 `allowed_updates`，照它部署增强版会导致功能缺失，请勿混用。

## 增强内容

1. **Cloudflare Turnstile 人机验证**
   - 待验证用户点击验证按钮后打开 Worker 自带的验证页，完成 Turnstile 校验即通过；验证链接以 Webhook 密钥做 HMAC 签名、绑定用户 ID、10 分钟过期，并核对 siteverify 返回的 hostname。
   - 验证方式在「网页管理台」里切换（见第 10 项）；未配置 Turnstile 密钥时自动回退原版静态问答验证，部署顺序与原版一致。
   - 新增可选环境变量：`TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY`；可选 `PUBLIC_URL` 覆盖验证页域名推导。

2. **消息反应（表情回应）双向同步**
   - 访客对消息贴/取消反应，话题中的对应消息同步；管理员在话题中贴/取消，访客侧同步（显示为机器人名义的反应）。
   - 仅同步普通 emoji，自定义表情跳过；机器人自身反应不回环；只对部署本版之后转发的新消息有效。

3. **消息编辑原地同步（替代原版的对比通知）**
   - 任一侧编辑消息，对侧对应消息原地更新（文字 `editMessageText` 并保留原格式、说明/媒体 `editMessageCaption` / `editMessageMedia`，媒体文件本身被替换时也能同步）。
   - 注：Telegram 对 Bot API 的编辑按静默编辑处理，不显示原生「已编辑」角标——所有机器人如此，非本版缺陷。
   - 无对应关系或原地编辑失败时，自动回退原版的「原内容/新内容」对比通知，编辑不会丢失。

4. **拉黑 / 解除拉黑提醒**（v1.0.1 新增）
   - 访客在私聊拉黑（停止）机器人时，其话题内即时出现提醒；解除拉黑同样提醒；D1 标记去重。上线前已被拉黑的用户，在管理员回复发送被拒时走同一标记兜底提醒。

5. **一行编辑提示（滚动更新）**
   - 原地编辑成功后补发一条 `✏️ 对方修改了这条消息`，以回复形式关联到被改的消息，作为「已编辑」的替代标记。
   - 同一条消息多次编辑时，先撤回上一条提示再发新的，每条消息只保留最新的一条提示。

6. **验证调试工具**（v1.0.2 新增）
   - 管理员私聊发送 `/testverify` 可生成测试模式的 Turnstile 验证链接：走完整校验流程但不写入任何用户记录，可反复自测验证是否配置正确。
   - 在用户话题里发送 `/reverify`，可把该用户重置为待验证状态（重新走一遍验证）。

7. **已验证用户超时清理**（v1.0.2 新增）
   - 配置项 `verified_ttl_days`（网页管理台可改，默认 0 = 关闭）：超过该天数无活跃的已验证/待验证用户会被自动清除（含其消息记录与话题映射；旧话题保留为无主存档，用户回来会新建话题）。管理员与协管员豁免，活跃自动续期。

8. **D1 不再保存消息正文**（v1.0.2 新增）
   - 转发只保存同步所需的消息配对关系，不再把访客消息正文写入数据库（原版会为编辑对比功能保存正文，最长 90 天）。编辑回退通知改为显示占位文字，不再复述原文。
   - 旧版本存量正文可在 D1 控制台执行 `DELETE FROM messages WHERE user_id != 'rxmap';` 立即清除，或等 90 天自动过期。

9. **网页版用户列表与数据统计**（v1.0.2 新增）
   - 主菜单的网页按钮打开用户列表（签名链接、30 分钟有效、仅主管理员）：可搜索、按状态筛选、排序分页，并可对用户重置验证或删除记录（可选连带删除话题）。
   - 列表顶部有数据统计区：用户总览（总数/已验证/待验证/未开始/已封禁/已静音/已拉黑机器人）与过去 24 小时 / 7 天 / 30 天的新增、活跃、消息量（访客/管理员回复）。消息量按同步映射记录统计，仅回溯 90 天，口径在页面明示。
   - 页面为「用户列表 / 数据统计」双标签页，默认停在列表页，统计不再挤占列表的可视区域；用户备注可在列表行内查看与编辑（见第 14 项），搜索可命中备注内容。

10. **网页管理台（配置全量网页化）**（v1.0.2 新增）
    - 原来在 Telegram 里逐个点按钮、等菜单刷新的配置方式已删除，全部搬到网页：主菜单点「🛠 网页管理台」打开（同一套签名鉴权、仅主管理员），基础配置（欢迎消息/验证问答/验证方式/超时天数）、按类型过滤、屏蔽关键词、自动回复、协管员名单都在页内表单完成，改完即时生效。
    - 旧聊天记录里残留的配置按钮点按只会提示已迁移；话题内的用户资料卡按钮与话题命令不受影响。
    - 基础配置中验证方式排在验证问题之前；选择 Turnstile 时，验证问题与验证答案两项自动隐藏，切回静态问答再显示。

11. **自动检查更新与命令菜单**（v1.0.2 新增）
    - 机器人会定期比对本仓库最新 Release，主菜单显示当前版本与更新状态；发现新版会私聊通知主管理员一次。主菜单有「🔄 检查更新」按钮，私聊命令 `/version` 也可查看。
    - 命令按作用域注册：私聊有 `/start`、`/help`、`/testverify`、`/version`，话题命令有 `/ban`、`/unban`、`/delete`、`/terminate`、`/card`、`/reverify`。

12. **话题服务消息静默忽略**（v1.0.2 新增）
    - 管理员在话题里关闭/重开/改名话题或置顶消息时，Telegram 会在话题里生成服务消息；原版会把这类消息误当作管理员回复去转发，被 Telegram 拒绝（the message can't be copied）后又在话题里误报「转发失败」。现已在话题回复入口静默忽略这类服务消息。

13. **引用转发保留（含部分引用）**（v1.0.2 新增）
    - 任一侧在回复时引用了某条消息，转发到对侧时会带上引用：被引用消息按配对关系换算到对侧的对应消息，访客看到的是引用着自己原话的回复，管理员在话题里看到的同理。
    - 在客户端框选一段文字的「部分引用」也会原样带过去（片段文字、位置与格式一并保留）；引用对不上或原消息已删除时自动降级（整条引用 → 普通消息），保证消息本身不丢。

14. **管理员备注**（v1.0.2 新增）
    - 话题命令 `/note 内容` 给当前话题用户存一条仅管理员可见的备注（上限 500 字、支持多行），`/note` 查看当前备注，`/notedelete` 删除；备注内容可能以数字开头也不会被误认为用户 ID，命令本身不会转发给访客。
    - 备注显示在话题资料卡上，保存/删除后资料卡自动原地刷新；网页用户列表里可查看、编辑备注，搜索可按备注内容命中。用户表新增 `admin_note` 字段，部署新版时自动迁移。

15. **新手引导（小白向网页版）**（v1.1.0 新增）
   - 管理员主菜单新增「📖 新手引导」网页按钮：点开是机器人自带的指南页（同一套签名鉴权、30 分钟有效、仅主管理员），部署和使用时不用再翻仓库文档，在 Telegram 里随时能查。
   - 全文九节：项目说明（双向客服原理、D1 不保存消息正文、免费额度）、开始使用四步、验证、接待日常、命令速查（话题命令与私聊命令）、网页管理台五区、用户列表与数据统计（90 天口径）、版本与更新、常见问题六则（关闭话题≠封禁、命令候选不弹多为客户端缓存、无原生「已编辑」标记、反应显示为机器人名义、验证失败排查、网页链接过期）。
   - 顶部章节导航点按跳转时，页面按置顶页眉的实际高度自动补偿滚动位置，手机窄屏下正文也不会被页眉挡住。

16. **/delete 连带删除私聊原消息**（v1.1.0 新增）
   - 在话题里回复某条转发消息发送 `/delete`，除删除话题侧消息并打墓碑外，现按消息配对连带删除客人私聊中的原消息；管理员回复的消息被 `/delete` 时，其发到客人私聊的副本同样删除。
   - 客人已自行删除的原消息视为已删、不额外提示；删除失败（如原消息超过 48 小时、机器人被拉黑）会在话题里留一行说明。
   - 说明：Telegram 原生删除（右键 / 长按删话题消息）不会通知机器人（Bot API 没有消息删除事件），无法自动同步，连带删除请通过 `/delete` 触发。

17. **备注同步到话题名**（v1.1.0 新增）
   - 话题名改为「备注｜名字 (ID)」：备注非空时取其第一行非空内容（单独限长 40 字）放在话题名最前面，在话题群的侧边栏列表里直接可见；无备注时与原格式一致。
   - 在话题里用 `/note` 设置、`/notedelete` 删除，或在网页用户列表里修改备注，话题名都会立即同步；客人改名触发的资料卡自动刷新同样带着备注，不会把前缀冲掉。

18. **网页用户列表一键跳话题**（v1.1.0 新增）
   - 用户列表每行（有话题的用户）新增「💬 话题」按钮，点按后直接跳到话题群里该用户的话题页面，省去回群翻找话题的步骤。

19. **三页浏览体验优化**（v1.1.0 新增）
   - 修复在 iPhone 的 Telegram 内置浏览器中打开新手引导页、点击章节按钮时置顶页眉闪烁（消失又出现）的问题；三页（指南 / 管理台 / 用户列表）页眉统一改为固定定位并按实测高度补偿，向上滚动时也不再闪；
   - 章节跳转改为平滑滚动动画，不再生硬跳变；动画由页面脚本逐帧驱动，不依赖系统动效设置，在 Telegram 应用内、iPhone 与桌面浏览器中表现一致；落点仍按页眉实际高度补偿，正文不被遮挡。指南页、管理台与用户列表等签名页面已加禁止缓存，网页视图不会再展示缓存中的旧页面；
   - 平滑滚动已推广到三页：网页管理台的章节按钮同样是逐帧动画跳转，用户列表切换标签、翻页、筛选、排序后平滑滚回顶部；指南页与管理台阅读时，页眉导航会高亮当前读到的章节；用户列表的标签页与筛选（全部 / 已验证 / 待验证 / 已屏蔽）切换带按方向滑动的动画。

20. **紧急熔断（暂停服务）**（v1.1.0 新增）
   - 被消息轰炸时可一键暂停机器人：主管理员在私聊或任意话题里发 `/pause [分钟]`（不带数字默认 60，上限 10080），或用主菜单的「⏸ 紧急暂停」按钮、网页管理台的「紧急熔断」区；`/resume` 随时恢复，到期自动恢复并私聊通知主管理员。
   - 暂停期间访客的消息、编辑与表情反应在入口直接丢弃、不转发；管理员与管理群侧不受影响。
   - 熔断回复：每位访客每轮暂停最多收到一条提醒（默认「请稍后再试」），语句可在网页管理台修改或关闭（管理台里选「关闭：完全静默」时，回复语句输入框会自动隐藏）；已被封禁的用户不会收到回复。

21. **熔断到期通知说明**（v1.1.0 新增）
   - 熔断到期后，恢复是「惰性」的：没有后台定时器，到期后第一条消息到来时才一并解除暂停并私聊通知主管理员；如果一直没人发消息，收不到恢复通知是正常的，熔断其实已经结束、只是没通知。
   - 开启熔断的确认消息（私聊 / 话题 / 主菜单已暂停状态行与选时长子菜单）、网页管理台提示与新手指南页都会把这件事写在明处，不会让人误以为机器人卡住了。

## 与原版部署的差异

除原版教程的变量（`BOT_TOKEN`、`ADMIN_IDS`、`ADMIN_GROUP_ID`、`WEBHOOK_SECRET` 与 D1 绑定 `TG_BOT_DB`）外：

1. 如需 Turnstile 验证，再加 `TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY` 两个变量（Turnstile 小部件的主机名填 Worker 域名）；不加则用原版问答验证。
2. 注册 Webhook 时必须带上 `allowed_updates`，且务必包含 `secret_token`，例如：

   `https://api.telegram.org/bot<机器人令牌>/setWebhook?url=<Worker地址>&secret_token=<你的WEBHOOK_SECRET>&allowed_updates=["message","edited_message","callback_query","message_reaction","my_chat_member"]`

   其中 `message_reaction` 是反应同步的前提，`edited_message` 是编辑同步的前提，`my_chat_member` 是拉黑提醒的前提，缺哪类就少哪类功能。
3. 机器人需要群组管理员的「删除消息」权限（编辑提示的滚动撤回要用）；置顶、删除话题等权限同原版教程。

其余部署步骤（建 D1、建 Worker、粘贴代码、绑定变量）与原版教程完全一致。
